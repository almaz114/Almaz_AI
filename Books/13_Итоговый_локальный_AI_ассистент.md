# 🚀 Глава 13. Итоговый локальный AI-ассистент

> **Главная цель главы:** объединить все изученные элементы в одну понятную архитектуру локального AI-ассистента: модель, контекст, RAG, Tools, Agent Loop и Fine-tuning.

- расширять его новыми Tools;
- подключить собственную базу знаний;

# 3. Роль локальной LLM

Локальная LLM отвечает за:

```text
понимание запроса
выбор действия
интерпретацию результатов
формирование ответа
```

Но она не должна заменять:

```text
базу данных
точные вычисления
файловую систему
API
актуальные документы
```

Для этого существуют Tools и RAG.

# 4. Роль RAG

RAG отвечает за поиск нужных знаний в собственных документах.

```text
User Question
↓
Retrieval
↓
Top-k Chunks
↓
Context
↓
LLM
↓
Answer
```

RAG не меняет weights модели.

# 5. Роль Tools

Tools выполняют точные действия:

```text
прочитать файл
посчитать
найти запись
получить данные из API
обработать таблицу
проверить структуру
```

LLM выбирает Tool, а Python реально его выполняет.

# 6. Роль Fine-tuning

Fine-tuning полезен для устойчивого изменения поведения:

```text
стиль ответа
структура
терминология
формат
доменные шаблоны
```

Сильная архитектура:

```text
Fine-tuned Local LLM
+
RAG
+
Tools
```

# 7. Где находится LoRA Adapter

Во время inference:

```text
Base Model
+
LoRA Adapter
↓
Effective Model
```

Для Controller это всё ещё один логический LLM-блок.

# 11. Assistant Controller

Controller управляет:

```text
историей сообщений
Tool Registry
RAG
числом шагов
разрешениями
ошибками
вызовом LLM
```

Это одна из ключевых частей всей системы.

# 12. Почему нельзя отдавать весь контроль LLM

LLM вероятностная и может:

```text
выбрать неправильный Tool
сформировать неверные аргументы
повторять одно действие
зациклиться
```

Поэтому Controller должен иметь жёсткие ограничения.

# 13. MAX_STEPS

```python
MAX_STEPS = 5
```

Так Agent Loop не сможет работать бесконечно.

# 14. Tool Registry

```python
TOOLS = {
    "add_numbers": add_numbers,
    "word_count": word_count,
    "search_knowledge_base": search_knowledge_base,
}
```

# 15. Read-only и Write Tools

Read-only:

```text
search
read
calculate
analyze
```

Write:

```text
save
delete
send
change
```

Write Tools требуют более строгих правил.

# 16. Human-in-the-loop

Для важных действий:

```text
Model proposes action
↓
User confirms
↓
Tool executes
```

# 17. История диалога

В Chat Context могут входить:

```text
System
User
Assistant
Tool Result
Assistant
...
```

История занимает Context Window, поэтому её иногда приходится сокращать или суммаризировать.

# 18. Short-term и Long-term Memory

```text
Short-term Memory
→ текущая история диалога

Long-term Memory
→ документы / RAG / база данных
```

# 22. Error Handling

Ошибиться может любой слой:

```text
LLM
Tool
RAG
файл
API
локальный runtime
```

Лучше возвращать структурированный результат:

```json
{
  "status": "error",
  "message": "..."
}
```

# 30. Tool Result должен быть реальным

```text
Tool Call
↓
Python executes
↓
Tool Result
↓
LLM
```

Модель не должна воображать, что действие произошло.
