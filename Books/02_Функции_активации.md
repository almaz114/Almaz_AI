# 1. Где находится функция активации

В первой главе мы уже видели искусственный нейрон:

```text
Входные значения
      ↓
Умножение на веса
      ↓
Суммирование
      ↓
Bias
      ↓
Функция активации
      ↓
Выход нейрона
```

Математически сначала вычисляется:

\[
z = x_1w_1 + x_2w_2 + \dots + x_nw_n + b
\]

После этого применяется функция:

\[
a = f(z)
\]

где:

- `z` — результат линейного преобразования;
- `f` — функция активации;
- `a` — значение, передаваемое дальше по сети.

# 2. Почему нельзя просто использовать Linear-слои

Представим сеть:

```text
Input
  ↓
Linear
  ↓
Linear
  ↓
Linear
  ↓
Output
```

На первый взгляд кажется, что три слоя должны быть значительно мощнее одного.

Но если между ними нет нелинейной функции, вся цепочка остаётся линейным преобразованием.

Упрощённо:

\[
y = W_3(W_2(W_1x + b_1)+b_2)+b_3
\]

Эту конструкцию можно математически свернуть в:

\[
y = Wx + b
\]

То есть несколько последовательных линейных слоёв без нелинейности можно представить как один линейный слой.

---

# 3. Что такое нелинейность

Линейная зависимость — это очень простой тип зависимости.

Например:

```text
y = 2x + 1
```

График представляет собой прямую линию.

Но реальные задачи значительно сложнее.

Например:

- распознавание изображений;
- понимание текста;
- классификация объектов;
- прогноз сложных процессов;
- анализ поведения пользователя.

Для моделирования таких зависимостей сети нужны нелинейные преобразования.

Именно это дают функции активации.

Упрощённая идея:

```text
Linear
  ↓
Activation
  ↓
Linear
  ↓
Activation
  ↓
Linear
```

Так сеть может строить значительно более сложные преобразования.

# 4. ReLU

Одна из самых распространённых функций активации:

**ReLU — Rectified Linear Unit**

Формула:

\[
ReLU(x) = \max(0, x)
\]

Правило очень простое:

```text
если x < 0 → 0
если x ≥ 0 → x
```

Примеры:

| Вход | ReLU |
|---:|---:|
| -5 | 0 |
| -1 | 0 |
| 0 | 0 |
| 1 | 1 |
| 5 | 5 |

---

![[Images/chapter02/02_relu.png]]

---

## Почему ReLU популярна

Она:

- очень проста;
- быстро вычисляется;
- не ограничивает положительные значения сверху;
- хорошо работает во многих глубоких сетях;
- часто помогает обучению идти быстрее, чем классические насыщаемые функции.

В PyTorch:

```python
nn.ReLU()
```

Именно эту строку мы уже использовали в сети «Светофор».

---

# 5. Проблема Dead ReLU

У ReLU есть недостаток.

Если нейрон начинает стабильно получать отрицательные значения:

```text
x < 0
```

то:

```text
ReLU(x) = 0
```

И производная на отрицательной части тоже равна нулю.

Такой нейрон может перестать эффективно обновляться.

Это явление часто называют:

**Dead ReLU — «мёртвый ReLU-нейрон».**

Важно понимать: это не означает, что ReLU плохая функция. Это один из известных компромиссов её простоты.

---

# 6. Sigmoid

Sigmoid преобразует любое число в диапазон:

```text
0 ... 1
```

Формула:

\[
\sigma(x) = \frac{1}{1 + e^{-x}}
\]

Примерно:

| Вход | Sigmoid |
|---:|---:|
| -10 | ≈ 0 |
| -2 | ≈ 0.12 |
| 0 | 0.5 |
| 2 | ≈ 0.88 |
| 10 | ≈ 1 |

---

![[Images/chapter02/03_sigmoid.png]]

---

## Интуитивный смысл Sigmoid

Она удобна, когда результат хочется интерпретировать как значение между 0 и 1.

Например:

```text
0.02 → почти точно НЕТ
0.50 → неопределённость
0.97 → почти точно ДА
```

В нашей задаче со светофором:

```text
0.08 → скорее СТОЯТЬ
0.92 → скорее ИДТИ
```

В PyTorch:

```python
nn.Sigmoid()
```

---

# 7. Где Sigmoid особенно полезна

Один из распространённых случаев — выход бинарного классификатора.

Например:

```text
спам / не спам
болен / здоров
идти / стоять
```

Но есть важная техническая деталь.

Если используется:

```python
nn.BCEWithLogitsLoss()
```

то **не нужно вручную ставить Sigmoid перед функцией потерь**.

`BCEWithLogitsLoss` уже объединяет логистическое преобразование и бинарную функцию потерь более численно устойчивым способом.

Правильная схема:

```text
Последний Linear
      ↓
Logits
      ↓
BCEWithLogitsLoss
```

А Sigmoid можно применить отдельно позже для интерпретации вероятности:

```python
probability = torch.sigmoid(logits)
```

---

# 8. Проблема насыщения Sigmoid

Посмотрим на крайние значения:

```text
x = -20 → Sigmoid ≈ 0
x = +20 → Sigmoid ≈ 1
```

На таких участках функция становится почти горизонтальной.

Это называется **насыщением — saturation**.

Когда функция находится в насыщенной области, её производная становится очень маленькой.

Следовательно, градиент тоже может становиться очень маленьким.

Это связано с известной проблемой:

**Vanishing Gradient — исчезающий градиент.**

Подробно градиенты мы будем изучать в следующей главе.

---

# 9. Tanh

`Tanh` — гиперболический тангенс.

Он преобразует значения в диапазон:

```text
-1 ... 1
```

Формула:

\[
\tanh(x)
\]

Примерно:

| Вход | Tanh |
|---:|---:|
| -10 | ≈ -1 |
| -2 | ≈ -0.96 |
| 0 | 0 |
| 2 | ≈ 0.96 |
| 10 | ≈ 1 |

---

![[Images/chapter02/04_tanh.png]]

---

## Чем Tanh отличается от Sigmoid

Главное различие диапазона:

```text
Sigmoid:
0 ... 1

Tanh:
-1 ... 1
```

У `Tanh` центр находится около нуля.

Это иногда удобно для скрытых представлений.

Однако у неё тоже есть насыщение на больших положительных и отрицательных значениях.

В PyTorch:

```python
nn.Tanh()
```

---

# 10. Leaky ReLU

`Leaky ReLU` похожа на обычную `ReLU`, но отрицательные значения не превращаются строго в ноль.

Упрощённо:

```text
x ≥ 0 → x

x < 0 → маленькая часть x
```

Например:

\[
LeakyReLU(x)=
\begin{cases}
x, & x \geq 0 \\
0.01x, & x < 0
\end{cases}
\]

---

![[Images/chapter02/05_leaky_relu.png]]

---

## Зачем это нужно

У обычной ReLU:

```text
-5 → 0
```

У Leaky ReLU при коэффициенте `0.01`:

```text
-5 → -0.05
```

То есть отрицательная часть сигнала не исчезает полностью.

Это уменьшает риск возникновения «мёртвых» нейронов.

В PyTorch:

```python
nn.LeakyReLU()
```

или, например:

```python
nn.LeakyReLU(negative_slope=0.01)
```

---

# 11. Быстрое сравнение

| Функция | Диапазон | Сильная сторона | Возможная проблема |
|---|---|---|---|
| ReLU | 0 ... ∞ | Простая и эффективная | Dead ReLU |
| Sigmoid | 0 ... 1 | Удобна для вероятности | Saturation |
| Tanh | -1 ... 1 | Центрирована около 0 | Saturation |
| Leaky ReLU | -∞ ... ∞ | Сохраняет слабый отрицательный сигнал | Нужно выбрать наклон |

# 12. Softmax — пока только обзорно

Есть ещё одна важная функция:

```text
Softmax
```

Она часто используется, когда модель выбирает **один класс из нескольких**.

Например:

```text
кошка
собака
машина
дом
```

Модель может получить значения:

```text
2.1
0.4
-1.2
0.8
```

Softmax преобразует их в распределение вероятностей, сумма которого равна 1.

Например:

```text
кошка   0.70
собака  0.13
машина  0.03
дом     0.14
```

Подробно Softmax мы разберём позже, когда дойдём до многоклассовой классификации.

Важное правило PyTorch:

если используется:

```python
nn.CrossEntropyLoss()
```

обычно не нужно вручную применять Softmax перед функцией потерь.

`CrossEntropyLoss` ожидает **logits**.

# 13. Где какие функции обычно встречаются

Очень грубая практическая карта:

```text
Скрытые слои современных сетей
        ↓
ReLU / Leaky ReLU / похожие функции

Бинарный выход
        ↓
Sigmoid для интерпретации вероятности

Многоклассовый выход
        ↓
Softmax для интерпретации вероятностей

Некоторые рекуррентные архитектуры
        ↓
Tanh / Sigmoid
```

Это не строгий закон.

Современные архитектуры используют также:

- GELU;
- SiLU / Swish;
- другие функции.

До них мы дойдём позже, особенно при изучении Transformer.

# 14. Функции активации в PyTorch

Основные варианты:

```python
import torch.nn as nn

relu = nn.ReLU()
sigmoid = nn.Sigmoid()
tanh = nn.Tanh()
leaky_relu = nn.LeakyReLU()
```

Пример:

```python
model = nn.Sequential(
    nn.Linear(3, 4),
    nn.ReLU(),
    nn.Linear(4, 1),
)
```

Строка:

```python
nn.ReLU()
```

находится между двумя линейными слоями.

Именно благодаря ей эти два линейных преобразования не сворачиваются просто в одно линейное преобразование.


примерно:

```text

```

примерно:


Уже по этим значениям видно, что каждая функция преобразует информацию совершенно по-разному.

# 22. Очень важный нюанс нашего светофора

Наша задача:

```text
ИДТИ = зелёный включён
       И
       красный выключен
```

достаточно проста и **линейно разделима**.

Следовательно, даже модель без скрытой нелинейности способна решить эту конкретную задачу.

Это важный учебный вывод.

Нельзя утверждать:

> «Если убрать ReLU, сеть всегда перестанет работать».

Правильнее:

> **Для сложных нелинейных задач функции активации позволяют многослойной сети моделировать зависимости, которые невозможно получить простой линейной композицией.**

А для простой задачи дополнительная нелинейность может быть просто не обязательна.

# 23. 🌍 Аналогия из жизни

Представим систему принятия решения о выдаче кредита.

Входы:

```text
доход
возраст
долги
история платежей
сумма кредита
```

Если использовать только простое линейное правило, система может вычислять что-то вроде:

```text
оценка =
доход × вес
- долги × вес
+ история × вес
...
```

Но реальные зависимости могут быть сложнее.

Например:

```text
высокий доход
+
очень высокая долговая нагрузка
```

может вести себя совсем иначе, чем простая сумма двух факторов.

Нелинейность позволяет сети строить более сложные комбинации признаков.

# 29. 🚀 Как это пригодится дальше

Мы уже понимаем:

```text
Input
 ↓
Weights
 ↓
Bias
 ↓
Activation
 ↓
Prediction
```

Но во время обучения появляется следующий вопрос:

> **Как модель понимает, насколько плох её ответ?**

Для этого используется:

```text
LOSS FUNCTION
```
