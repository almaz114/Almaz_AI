# 1. Что такое Fine-tuning

Большая языковая модель сначала проходит огромное предварительное обучение:

```text
Pretraining
↓
огромный общий Dataset
↓
базовые языковые способности
↓
Base Model
```

После этого модель можно дополнительно обучить на более узком наборе примеров:

```text
Base Model
↓
ваш специализированный Dataset
↓
Fine-tuning
↓
адаптированная модель
```

---

![[Images/chapter12/01_base_vs_finetuned.png]]

---

# 2. Fine-tuning не означает обучение с нуля

При обучении с нуля:

```text
случайные weights
↓
огромный Dataset
↓
долгое обучение
```

При Fine-tuning:

```text
уже обученные weights
↓
небольшой специализированный Dataset
↓
дополнительное обучение
```

Поэтому Fine-tuning обычно требует значительно меньше данных и ресурсов, чем Pretraining.

---

# 3. Что мы хотим изменить

Fine-tuning может быть полезен, чтобы изменить:

```text
стиль ответа
формат ответа
следование специальным инструкциям
терминологию домена
типичные шаблоны решения
устойчивое специализированное поведение
```

Он также может помочь модели лучше использовать предметные понятия и устойчивые закономерности.

Но это не то же самое, что создать надёжную базу точных фактов.

---

# 4. Fine-tuning и знания

Представим устойчивое предметное утверждение:

```text
"На рынке большую часть времени может преобладать
боковое движение, а трендовые периоды встречаются реже."
```

Такой тип доменной концепции можно включать в Fine-tuning Dataset.

Но важно понимать:

> Fine-tuning не превращает модель в гарантированную базу данных.

Если нужны точные значения, документы, правила или часто обновляемые факты, RAG обычно надёжнее.

---

# 5. RAG и Fine-tuning решают разные задачи

```text
RAG
→ что модель должна иметь в контексте прямо сейчас

Fine-tuning
→ как модель должна отвечать и работать
```

Например:

```text
актуальный договор
→ RAG

специализированный стиль анализа
→ Fine-tuning

точное значение из документа
→ RAG

устойчивая терминология предметной области
→ Fine-tuning может быть полезен
```

# 6. Supervised Fine-Tuning — SFT

Один из самых распространённых видов Fine-tuning:

```text
Supervised Fine-Tuning
```

Модель получает примеры правильного поведения:

```text
Instruction
↓
Expected Answer
```

Например:

```text
Пользователь:
Что такое флет?

Ассистент:
Флет — состояние рынка, при котором цена...
```

---

# 7. Instruction Dataset

Простейшая логика Dataset:

```text
Input
→ Instruction / Question

Target
→ Desired Answer
```

Для Chat Model часто используют сообщения:

```json
{
  "messages": [
    {
      "role": "user",
      "content": "Что такое тренд?"
    },
    {
      "role": "assistant",
      "content": "Тренд — устойчивое направленное движение цены..."
    }
  ]
}
```

---

![[Images/chapter12/02_training_dataset_format.png]]

# 8. Качество Dataset важнее количества строк

Плохой Dataset:

```text
противоречивые ответы
ошибочные факты
разный стиль
дубли
непонятные инструкции
много мусора
```

может ухудшить модель.

Хороший Dataset:

```text
точный
последовательный
чистый
разнообразный
соответствует реальной задаче
```

---

# 9. Train и Validation

Dataset полезно разделять:

```text
Train
↓
на нём обновляются параметры

Validation
↓
на нём проверяем качество
```

Если модель отлично работает только на Train, возможно:

```text
Overfitting
```

---

# 10. Full Fine-tuning

При Full Fine-tuning обучаются практически все параметры модели.

```text
Base weights
↓
Gradients
↓
Optimizer
↓
изменяются миллиарды параметров
```

Для больших LLM это требует много:

```text
VRAM
RAM
времени
вычислений
```

---

# 11. Почему появился PEFT

PEFT:

```text
Parameter-Efficient Fine-Tuning
```

Идея:

> не обучать миллиарды исходных параметров, а добавить небольшой набор обучаемых параметров.

Один из самых известных подходов:

```text
LoRA
```

---

# 12. Главная идея LoRA

Представим Linear-слой с матрицей:

```text
W
```

Вместо изменения всей `W`, LoRA добавляет небольшое обновление:

\[
W' = W + \Delta W
\]

где:

\[
\Delta W = BA
\]

Матрицы `A` и `B` значительно меньше исходной `W`.

---

![[Images/chapter12/03_lora_low_rank.png]]

---

# 13. Что означает Low-Rank

Пусть исходная матрица:

```text
W: [4096, 4096]
```

Это:

```text
16 777 216 параметров
```

LoRA может использовать rank:

```text
r = 8
```

Тогда:

```text
A: [8, 4096]
B: [4096, 8]
```

Количество LoRA-параметров:

```text
8 × 4096
+
4096 × 8
=
65 536
```

Это намного меньше 16,7 млн.

---

# 14. Base Model замораживается

При LoRA:

```text
Base weights
requires_grad = False
```

А обучаются:

```text
LoRA A
LoRA B
```

То есть Gradient Descent изменяет только небольшой Adapter.

---

# 15. LoRA Adapter

После обучения можно хранить отдельно:

```text
Base Model
+
LoRA Adapter
```

Adapter обычно намного меньше всей модели.

Это удобно:

```text
одна Base Model
+
Adapter Forex
+
Adapter Coding
+
Adapter Support
```

---

# 16. Rank r

Параметр:

```text
r
```

задаёт внутреннюю размерность LoRA.

Меньший rank:

```text
меньше параметров
меньше памяти
меньше гибкости
```

Больший rank:

```text
больше параметров
больше возможностей адаптации
```

---

# 17. LoRA Alpha

В LoRA часто используется масштабирование:

```text
alpha
```

Упрощённо оно регулирует силу LoRA-обновления.

Часто встречается выражение:

\[
scale = \frac{\alpha}{r}
\]

---

# 18. LoRA Dropout

Также может использоваться:

```text
lora_dropout
```

Он работает как обычный Dropout внутри LoRA-ветки и может помогать против переобучения.

---

# 19. Какие слои обычно адаптируют

В Transformer LoRA часто добавляют к Linear-проекциям Attention и другим Linear-слоям.

Можно встретить названия:

```text
q_proj
k_proj
v_proj
o_proj
```

а также проекции Feed-Forward сети.

Конкретные target modules зависят от архитектуры модели.

---

# 20. Что такое QLoRA

QLoRA объединяет две идеи:

```text
Quantized Base Model
+
LoRA Adapters
```

Базовая модель хранится в низкой точности, а небольшие LoRA-параметры обучаются.

---

![[Images/chapter12/04_qlora_quantized_training.png]]

---

# 21. Зачем QLoRA

Главная причина:

```text
экономия VRAM
```

Упрощённо:

```text
Full Fine-tuning
→ очень дорого

LoRA
→ дешевле

QLoRA
→ ещё доступнее по памяти
```

Это особенно важно для локальных экспериментов и облачных GPU с ограниченной VRAM.

---

# 22. Quantization здесь не означает, что всё обучение идёт в 4-bit

Базовые weights могут храниться в низкой точности.

Но вычисления и обучаемые LoRA-параметры используют подходящую рабочую точность.

То есть QLoRA — не просто:

```text
"сделать всё 4-bit"
```

а более продуманная схема экономии памяти.

---

# 24. Epoch

Epoch:

```text
один полный проход по Train Dataset
```

Для Fine-tuning LLM слишком большое число Epoch может привести к переобучению.

---

# 25. Learning Rate

Learning Rate определяет размер шага обновления параметров.

Слишком большой:

```text
обучение нестабильно
можно испортить поведение
```

Слишком маленький:

```text
обучение идёт слишком медленно
изменения могут быть слишком слабыми
```

---

# 26. Batch Size

Batch Size показывает, сколько обучающих примеров участвует в одном шаге.

Для LLM память часто ограничивает Batch Size.

Поэтому используют:

```text
Gradient Accumulation
```

---

# 27. Gradient Accumulation

Если физически помещается только:

```text
Batch = 1
```

можно несколько шагов накапливать gradients и только потом делать:

```text
optimizer.step()
```

Так получается больший эффективный Batch Size.

---

# 28. Sequence Length

Каждый обучающий пример после Tokenization имеет длину в Tokens.

Большая Sequence Length:

```text
больше контекста
+
намного больше памяти и вычислений
```

Поэтому этот параметр критичен для Fine-tuning.

---

# 29. Overfitting

Если Dataset маленький и модель обучать слишком долго:

```text
Train Loss ↓
```

но реальное качество может ухудшаться.

Модель начинает слишком точно повторять обучающие примеры.

Это Overfitting.

---

# 30. Хороший тест после Fine-tuning

Не нужно проверять модель только теми же вопросами, которые были в Dataset.

Нужны новые формулировки:

```text
Train:
"Что такое боковой рынок?"

Test:
"Как называется состояние, когда цена долго движется в диапазоне?"
```

Так мы проверяем обобщение.

---

# 31. Fine-tuning ≠ Prompt Engineering

Prompt Engineering:

```text
weights не меняются
```

Fine-tuning:

```text
обучаемые параметры изменяются
```

Prompt можно поменять за секунды.

Fine-tuning требует Dataset и Training Run.

---

# 32. Fine-tuning ≠ RAG

RAG:

```text
получает внешний Context
```

Fine-tuning:

```text
изменяет обучаемые параметры
```

В сильной системе можно использовать вместе:

```text
Fine-tuned Model
+
RAG
+
Tools
```

---

# 33. Что разумно Fine-tune

Хорошие кандидаты:

```text
стиль анализа
структура ответа
терминология
формат JSON
типичные инструкции
устойчивые доменные шаблоны
классификация по вашим правилам
```

---

# 34. Что лучше не пытаться хранить только Fine-tuning

Например:

```text
текущая цена EURUSD
последняя версия документа
актуальный остаток в БД
сегодняшние новости
часто меняющиеся правила
```

Для этого лучше:

```text
RAG
Tools
API
Database
```
